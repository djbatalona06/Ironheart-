# Phase 6: PWA + polish

## Built
- **Service worker** (`public/sw.js`, hand-written): cache-first static assets, network-first pages (3s) → cached page → `/offline`, RSC payloads in a separate cache, image cache, never caches Supabase/API/auth; cleared on sign-out
- **Manifest** (`app/manifest.ts`), icons generated by `scripts/icons.mjs` (192/512/maskable/apple-180), apple-touch-icon + status-bar metadata
- **iOS install tip** from the 2nd visit (iOS has no install prompt), dismissible
- **Security headers** (nosniff, frame DENY, referrer policy, camera-only permissions policy, strict CSP + no-store on `sw.js`)
- Loading skeleton, error boundary (offline-aware), 404 page
- **Bundle diet**: Dexie and supabase-js are lazy-loaded after hydration on global components → first-load JS **136–172 KB gzip** (budget 200 KB)
- `SETUP.md`, `e2e/README.md`, refreshed README; docs 01/07/11/12 synced with what was built

## Tests
- `e2e/pwa.mjs`: manifest/icons, SW controls the page, `sw.js` uncached, **stops the server** to prove cached pages load and unvisited pages fall back to `/offline` (Playwright's offline mode doesn't reach service-worker fetches)
- Full suite run twice in a row: 14 unit · 70 SQL · **73 E2E**, all green

## Bugs found and fixed in this phase
- HTML and RSC responses shared a cache key, so an offline navigation could get a raw RSC payload → split caches
- Several E2E checks didn't wait for streamed content once `loading.tsx` existed → `seen()` helper
